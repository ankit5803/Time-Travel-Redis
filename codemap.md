| Category            | Concept to Master                   | CV / Interview Talking Point                                                                                                                                                                                                                                      |
| ------------------- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Networking**      | **TCP/IP vs. HTTP**                 | Explain why databases use raw TCP sockets. Highlight the elimination of HTTP header overhead and the necessity of persistent, full-duplex communication pipes for maximum throughput.                                                                             |
| **Networking**      | **Socket Mechanics**                | Describe the TCP handshake, port binding (e.g., port 6379), and how operating systems assign ephemeral ports for client connections.                                                                                                                              |
| **Protocols**       | **Binary-Safe Serialization**       | Detail the RESP (REdis Serialization Protocol). Explain why parsing based on byte-length prefixes (e.g., `$5\r\n`) avoids the massive CPU overhead associated with scanning for closing brackets or escape characters in JSON.                                    |
| **Concurrency**     | **The Event Loop**                  | Differentiate single-threaded cooperative multitasking (`asyncio`) from multithreading. Explain how yielding control back to the loop during I/O waits prevents context-switching overhead.                                                                       |
| **Concurrency**     | **Non-Blocking I/O**                | Explain how `await` prevents a slow client connection from freezing the entire database, allowing a single thread to juggle thousands of sockets simultaneously.                                                                                                  |
| **Data Structures** | **Hash Maps (Dictionaries)**        | Justify the use of native hash maps for the core database by explaining Big O notation—specifically, how hash maps achieve $O(1)$ average time complexity for `GET`, `SET`, and `DEL`.                                                                            |
| **Data Structures** | **Circular Buffers (Ring Buffers)** | Explain the Time-Travel Tombstone Buffer architecture. Contrast `collections.deque(maxlen=100)` with standard lists, noting that appending to a full ring buffer automatically drops the oldest item in $O(1)$ time rather than requiring an $O(n)$ memory shift. |
| **System Design**   | **Cache Eviction Strategies**       | Differentiate between **Lazy Eviction** (purging an expired key only when a user attempts to access it) and **Active Eviction** (a background process sweeping and freeing memory proactively).                                                                   |
| **System Design**   | **The API Bridge Pattern**          | Explain how to safely expose a low-level, raw TCP daemon to a modern web frontend by wrapping it with an intermediate HTTP/WebSocket proxy (FastAPI).                                                                                                             |

**Recommended Study Flow**

- **Step 1:** Trace the lifecycle of a single command (`GET name`) from the moment the Next.js UI sends an HTTP request, through the FastAPI bridge, down the TCP socket, through the RESP parser, into the Hash Map, and back.
- **Step 2:** Diagram the Memory structures on a whiteboard. Draw the main dictionary and the circular buffer side-by-side to visualize how data moves when a TTL expires.
- **Step 3:** Review Python `asyncio` documentation specifically focusing on `StreamReader` and `StreamWriter` to solidify how bytes are buffered in memory before parsing.
